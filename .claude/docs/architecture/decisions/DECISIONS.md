# Décisions

| Date | Décision | Pourquoi | Alternatives écartées |
|---|---|---|---|
| 28/09/2026 | Three.js plutôt qu'une librairie de cartographie | Le rendu diorama (socle découpé, style maquette) est plus simple à maîtriser en 3D pure | MapLibre (rendu carte réaliste), CesiumJS (trop lourd) |
| 28/09/2026 | Pas de backend, site 100 % statique | POC ; hébergeable partout (Pi/Coolify, Netlify) | API + PostGIS (plus tard si besoin) |
| 28/09/2026 | Données OSM pré-calculées en un fichier `city.json` | Chargement rapide, pas d'appel Overpass côté utilisateur | Requête Overpass au chargement |
| 28/09/2026 | Positions des lieux tirées d'OSM par leur nom, surchargeables avec `pos` | Ne jamais inventer de coordonnées | Coordonnées saisies à la main dès le départ |
| 28/09/2026 | Hauteurs estimées quand OSM n'a rien | Débloquer le POC ; BD TOPO ensuite | Tout à hauteur fixe |
| 28/09/2026 | Progression en localStorage, sans compte | Suffisant pour tester avec les amis | Comptes utilisateurs |
| 28/09/2026 | Outil de placement branché sur le serveur Vite (écrit `pois.json`), chargé seulement en dev | Saisie des lieux sans copier-coller, zéro code en production | Copier-coller manuel seul ; back-office séparé |
| 28/09/2026 | Toits en pente posés sur le rectangle orienté minimal, seulement pour les emprises quasi rectangulaires | Simple et robuste ; le squelette droit (toutes formes) est bien plus complexe | Squelette droit dès maintenant ; toits plats partout |
| 28/09/2026 | Forme de toit choisie au hasard (déterministe) quand OSM ne la donne pas | 97 % des bâtiments n'ont pas de `roof:shape` | Même forme partout (monotone) |
| 28/09/2026 | Squelette droit via `straight-skeleton` (CGAL/WASM), calculé dans le script de données | Algorithme robuste difficile à écrire soi-même ; précalcul = pas de WASM de 2 Mo dans l'app | Implémentation maison ; calcul dans le navigateur |
| 28/09/2026 | Le script de données décide du type de toit, l'app se contente de dessiner | Une seule source de vérité, pas de logique dupliquée, données plus légères | Garder la décision côté app (obligeait à stocker tous les squelettes) |
| 28/09/2026 | Tilt-shift en espace écran (bande horizontale) plutôt qu'un flou basé sur la profondeur | C'est le rendu « photo de maquette » classique, léger et prévisible | Profondeur de champ réelle (BokehPass) : plus coûteux, rendu moins typé maquette |
| 28/09/2026 | Fenêtres calculées dans le shader plutôt que modélisées | Zéro géométrie ni donnée en plus ; suffisant à l'échelle du diorama | Modéliser les fenêtres ; textures de façade |
| 28/09/2026 | Bars mis en avant par type de lieu, sans horaires réels | Simple pour le POC ; `opening_hours` OSM à parser plus tard | Parser les horaires dès maintenant |
| 28/09/2026 | Monuments : tester d'abord une seule fontaine en formes codées, avec un système qui accepte ensuite un vrai glTF | Valider l'intérêt avant d'investir des heures de modélisation | Modéliser directement les 3 monuments dans Blender |
| 28/09/2026 | Relief : RGE ALTI (IGN) avec repli par interpolation des sols BD TOPO ; zones au sol peintes sur une texture, rues drapées | Données officielles ; le repli garde un relief plausible hors ligne ; la texture évite de trianguler finement chaque parc | Relief plat ; modèle de terrain raster (GeoTIFF) plus lourd à décoder |
| 28/09/2026 | Pack nature : sources .obj dans `assets-src/`, conversion en .glb d'un seul maillage à couleur par sommet, couleurs remplacées par la palette du diorama | Fichiers 5 à 10 fois plus légers, 1 appel de rendu par modèle (instanciation), arbres cohérents avec le reste de la ville | Charger les .obj/.fbx directement (plus lourds, plusieurs matériaux) ; garder les couleurs d'origine (trop sombres) |
| 28/09/2026 | Arbres modélisés sur les emplacements existants, zone par zone (`nature.json`) | Pas de nouvelles données ; repli automatique sur les arbres simples ; charge maîtrisée | Remplacer tous les arbres de la ville d'un coup |
| 28/09/2026 | La Leysse dessinée à l'air libre même sur ses tronçons couverts (réglable) | Demande de Dasco : rivière continue et lisible | Fidèle au terrain (rivière interrompue) ; tracé discret sous la chaussée |
| 29/09/2026 | Mode hors-ligne avec vite-plugin-pwa (Workbox), mise à jour proposée par un bandeau | Précache fiable et révisions calculées automatiquement ; l'utilisateur n'est jamais rechargé en pleine exploration | Service worker écrit à la main ; mise à jour automatique avec rechargement |
| 29/09/2026 | Empreinte unique des données dans l'URL (`?v=`) plutôt que des noms de fichiers à empreinte | Aucun changement des chemins ni du script de données ; une seule empreinte pour tout (≈ 2 Mo) | Empreinte par fichier (invalide moins, mais plus complexe) |
| 29/09/2026 | Données régénérées au build Docker (REFRESH_DATA), avec repli sur les données du dépôt si une source manque | Demande de Dasco : un build = projet à jour ; le repli évite un build cassé ou une carte dégradée quand un service externe est en panne | Données seulement du dépôt (reproductible mais à régénérer à la main) ; build qui échoue si une source manque |
| 29/09/2026 | Déploiement : image Docker Node → nginx, via docker compose sur Coolify | Site statique, image finale légère sans Node ; compose prêt à accueillir un back-end plus tard (ex. PocketBase) | Buildpack statique ou Nixpacks de Coolify (moins de contrôle sur le cache) ; Dockerfile seul |
| 29/09/2026 | Cache : revalidation (no-cache + ETag) pour les données à nom fixe plutôt que des URL versionnées | Aucune modification du code ; jamais d'ancienne carte après une mise à jour | Numéro de version dans l'URL (cache long, à ajouter avec le mode hors-ligne) |
| 29/09/2026 | Ombres recalculées à la demande (soleil qui bouge), objets animés sans ombre | La scène est statique la plupart du temps : inutile de refaire la carte des ombres à chaque image | Ombres à chaque image (coût doublé) ; pas d'ombres du tout |
| 29/09/2026 | Arbres simplifiés à 50 % à la conversion (meshoptimizer), réglable dans nature.json | Moitié moins de triangles, différence à peine visible | Garder les modèles complets ; niveaux de détail (plus complexe, pour plus tard) |
| 29/09/2026 | Fiche des lieux positionnée avec left/top, jamais avec transform | Laisse transform libre pour les animations CSS | transform: translate (entrait en conflit avec l'animation de rebond) |
| 29/09/2026 | Effet maquette permanent, sans interrupteur | Demande de Dasco : c'est l'identité visuelle du diorama | Bouton pour le couper (retiré) |
| 29/09/2026 | Filtre des lieux par catégorie (une case par catégorie dans la légende), non mémorisé | Demande de Dasco ; une seule rangée de boutons | Case unique pour toute la couche (remplacée) ; menu de filtres séparé |
| 28/09/2026 | Étiquettes en sprites (toujours face caméra) | Lisibles sous les arbres et sous tous les angles | Texte posé au sol (caché par les arbres) |
| 29/09/2026 | Heure réelle de Chambéry (Europe/Paris) par défaut, relue chaque minute ; ombres recalculées au plus une fois par minute | Le soleil bouge d'environ 0,25° par minute : invisible en dessous ; une carte d'ombres par minute ne coûte rien | Heure de l'appareil (faux pour un visiteur à l'étranger) ; mise à jour à chaque image |
| 29/09/2026 | Position du soleil calculée dans le code (formules SunCalc / Meeus), sans dépendance | 40 lignes, vérifiées contre un calendrier solaire (lever/coucher à ±1 min) | Bibliothèque suncalc (dépendance de plus pour 2 fonctions) |
| 29/09/2026 | Hauteur de la lumière du soleil plafonnée à ≥ 7° au lever/coucher | Ombres rasantes trop longues pour le plateau ; l'ambiance (couleurs) suit tout de même la vraie hauteur | Hauteur réelle jusqu'à l'horizon |
| 29/09/2026 | Saisons par état du feuillage (vert / automne / nu) avec dates approximatives, saison choisie = date typique | Les arbres ne suivent pas le calendrier ; une date typique donne aussi la bonne course du soleil | Saison calendaire stricte (arbres nus dès le 21 décembre seulement) |
| 29/09/2026 | Lecture des horaires OSM maison, formes courantes seulement ; fériés et vacances ignorés, textes libres = « inconnu » (lieu allumé) | 104 / 106 horaires de Chambéry lus avec ~100 lignes ; ne jamais éteindre un lieu sans certitude | Bibliothèque opening_hours.js (complète mais ≈ 200 Ko) |
| 29/09/2026 | Vercel en plus de Docker/Coolify, avec les mêmes règles de cache dans `vercel.json` | Test d'hébergement de Dasco ; HTTPS et prévisualisation par branche sans configuration | Garder uniquement Coolify sur le Pi |
| 30/09/2026 | Mascotte : marche animée dans le shader d'après la position des sommets, déplacement sur le graphe des voies OSM | Le modèle fourni n'a pas de squelette ; le shader évite de le rigger dans Blender. Le graphe garantit qu'il reste sur les rues et chemins | Rigger le modèle (Blender) ; déplacement libre avec évitement ; modèle en formes simples |
| 30/09/2026 | Mini-jeu : l'éléphant est « coincé » quand toutes les issues d'un carrefour repartent vers la souris, sans zones de coin prédéfinies | Marche partout (culs-de-sac, bouts de carte, angles fermés par le joueur) sans rien placer à la main | Coins marqués à la main ; coincé dès qu'il est près d'un mur |
| 30/09/2026 | Points gardés dans le navigateur, séparés de la progression de découverte | Les points sont une monnaie à dépenser plus tard : « Recommencer l'exploration » ne doit pas les effacer | Un seul état pour tout |
| 30/09/2026 | Mini-jeu : cache-cache (disparition au survol, indice de rue, épuisé après 1 à 5 fuites) avec 4 éléphants à ramener sur la fontaine, à la place de « coincer l'éléphant » | Retour de Dasco : impossible de le coincer, la souris est trop rapide. | 30/09/2026 | Particules calculées sur le processeur, un objet Points par système, mélange normal | Quelques centaines de particules : simple, un appel de rendu ; le mélange additif disparaissait de jour sur les tons clairs | Particules sur le GPU (inutile à cette échelle) ; mélange additif |

| 30/09/2026 | Suivi du projet déplacé de `claude/` vers `.claude/docs/`, consignes réunies dans `.claude/CLAUDE.md` ; workflow hybride : itérations pour les petites demandes, epic + user stories pour les gros chantiers ; ce tableau reste l'index des décisions, un ADR seulement pour les décisions structurantes | Préparer les sub-agents (ils lisent `context.md` et écrivent leurs plans dans `tasks/`) sans alourdir les petites itérations ni découper 40 décisions d'une ligne | Epics/US pour toute demande ; itérations seules ; un ADR par décision ; garder `claude/` à côté de `.claude/` |
| 30/09/2026 | Chaque déploiement publie une nouvelle version des données (`generatedAt` dans `city.json`, donc nouvelle empreinte `?v=`) : bandeau « Nouvelle version » et nouveau téléchargement pour les visiteurs | Voulu par Dasco : un déploiement suit un ajout de fonctionnalité ou une correction, les données doivent alors être rechargées ; entre deux déploiements, elles restent en cache (nginx, service worker) | Retirer `generatedAt` pour ne changer l'empreinte que si la carte change (proposé par l'audit du 30/09) |
| 30/09/2026 | Boucle de rendu : liste ordonnée de modules `Ticker { update(dt, t) }` ; les modules dont la signature diffère sont branchés par une petite fonction dans la liste ; caméra (vol, contrôles), résolution adaptative et rendu restent hors de la liste | Ajouter un module = une ligne, sans toucher aux signatures existantes ; l'ordre reste visible à un seul endroit ; la caméra doit être à jour avant tous les modules et le rendu passer après | Changer la signature de chaque module ; un système d'abonnement (`loop.add()`) dispersé dans les fichiers, où l'ordre devient implicite |
| 30/09/2026 | Cadence : 30 images/s au repos, pleine vitesse pendant les mouvements ; mouvement de caméra détecté en comparant sa position d'une image à l'autre, le reste signalé par chaque module (`Ticker.moving()`) ; 0,5 s de marge après la caméra et la souris | Les éléphants marchent en permanence : impossible d'arrêter le rendu, on limite la cadence. Premier chargement identique (216 Ko gzip au total), fichiers à empreinte déjà en cache 1 an (nginx, Vercel) | Ne rien changer (retélécharger 216 Ko à chaque déploiement) ; découpage par écran (`import()` du jeu, des fiches) : trop peu de code à part, pour un gain incertain |
